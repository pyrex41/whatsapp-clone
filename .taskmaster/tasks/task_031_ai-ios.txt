Manual test script (primary acceptance)
1) Launch app, open an existing thread. Confirm a Smart Reply bar appears with 2–3 chips within 1.5s of view appear.
2) Tap the first chip. Composer populates exactly with chip text; caret at end; chips hide or remain per design.
3) Tap Send. Message appears immediately (optimistic). Feedback is recorded as decision=accepted with suggestionId; no modifiedContent.
4) Modify flow: tap a chip, append text, send. Feedback recorded as decision=modified with modifiedContent.
5) Error paths: simulate offline via `NetworkMonitor.shared.simulateOffline()` (DEBUG) and confirm a non-blocking error state on the Smart Reply bar with a retry button; normal sending still works.
6) Cache behavior: navigate away and back within 60s; bar repopulates using cache instantly, with background refresh deferred.

Best-practice implementation notes
- Determinism: inject a `Clock`/`DateProvider` into `SmartReplyService` to test TTL precisely; avoid sleeping.
- Isolation: prefer protocol-driven DI (`SmartReplyServiceProtocol` or extend `AIServiceProtocol`) so UI can be previewed with an in-memory mock.
- Resilience: debounce re-fetch on rapid thread switches; guard against duplicate taps; clamp chip count to 3.
- Telemetry: log accept/modify/reject with OSLog (privacy .private) in DEBUG only.
- Accessibility: ensure chips have readable labels and hit targets ≥44pt; VoiceOver reads chip text and “double tap to insert”.

# Test Strategy:
Unit/Integration (XCTest)
- Fetch success: service returns 3 suggestions; assert decoding, order, and non-empty ids/text.
- Caching TTL: first fetch hits network; second within 60s is cache; after advancing mock clock >60s, network called again.
- Feedback accepted: tap path leads to POST /api/v1/ai/record_feedback with decision=accepted and correct suggestionId.
- Feedback modified: modify composer before send; expect decision=modified with modifiedContent present.
- Feedback rejected: simulate chip swipe-to-dismiss; expect decision=rejected with optional reason field.
- Headers/auth: Authorization and JSON headers present on both endpoints.
- Error mapping: assert 401→unauthorized, 429→rateLimited(retryAfter), 5xx→backendError, bad JSON→decodingError.

UI (XCUITest)
- Happy path: open chat → wait for SmartReplyBar → tap chip → composer fills → send → new message bubble appears.
- No suggestions state: backend returns empty array → bar hidden or shows placeholder; ensure no layout jank.
- Offline: simulate offline via DEBUG hook; bar shows retry affordance; composer send still works for typed text.
- Accessibility: VoiceOver labels on chips and bar; ensure chips are hittable and visible with large text sizes.

How to run
- Scheme: run `GlobalBridgeTests` and `GlobalBridgeUITests` in Xcode. From CLI, use `xcodebuild test -scheme GlobalBridge -destination 'platform=iOS Simulator,name=iPhone 15'` with appropriate test targets.
