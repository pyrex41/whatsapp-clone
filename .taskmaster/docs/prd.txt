## Executive Summary

This PRD outlines critical security fixes, performance improvements, and architectural simplifications for the GlobalBridge AI backend. The code review identified **21 issues** across security, quality, performance, and architecture dimensions. This document prioritizes the most critical fixes and proposes a simplified caching strategy.

**Impact**:
- Eliminates critical security vulnerabilities (unauthorized thread access)
- Prevents cost explosion and DoS attacks
- Fixes data corruption bugs in vector embedding pipeline
- Simplifies caching architecture for better maintainability

**Timeline**: 2-3 weeks for full implementation

## Problem Statement

### Critical Issues Requiring Immediate Attention

1. **Security Vulnerability**: AI endpoints (`summarize_thread`, `extract_tasks`, `search_semantic`, `vec_health`) lack thread-level authorization checks, allowing users to access any thread's data.

2. **DoS & Cost Explosion**: AI endpoints have no rate limiting, enabling abuse of expensive OpenAI/Anthropic API calls.

3. **Data Corruption Bug**: Batch embedding reconstruction in `EmbeddingService.generate_batch/1` can mismatch embeddings to source texts, corrupting vector search indexes.

4. **Operational Blind Spot**: Cost tracking logs to console only - production costs are not persisted or queryable.

5. **Architectural Complexity**: Four caching layers (Redis, ETS, Cachex, persistent_term) create unnecessary complexity and maintenance burden.

defmodule GlobalbridgeBackend.AI.Authorization do

  alias GlobalbridgeBackend.Contexts.Threads
  require Logger

  @doc """
  Verifies user has access to thread. Returns :ok or {:error, :forbidden}.

  end

### 3. CRITICAL: Fix Batch Embedding Reconstruction

**Priority**: P0 (Critical)
**Effort**: 4 days
**Risk**: High - Data corruption

#### Problem Description

Current `EmbeddingService.generate_batch/1` implementation has two critical bugs:

1. **Alignment Bug** (lines 348-350): `Enum.zip(optimized_texts, uncached_results ++ cached_embeddings)` creates misaligned mappings when `uncached_results` is an error tuple
2. **Error Handling Bug** (lines 139-147): Error tuples from API flow into reconstruction logic expecting lists

#### Functional Requirements

- **FR-3.1**: Batch embedding generation MUST maintain strict alignment between input texts and output embeddings
- **FR-3.2**: API errors MUST short-circuit batch processing (fail fast)
- **FR-3.3**: Partial batch failures MUST NOT corrupt successful embeddings
- **FR-3.4**: Reconstruction logic MUST use efficient O(n) lookups via Map

#### Technical Specification

```elixir
# Fixed implementation in embedding_service.ex
def generate_batch(texts) when is_list(texts) do
  optimization_result = CostOptimizer.optimize_batch_queries(texts, :embedding)
  optimized_texts = optimization_result.optimized_queries

  Logger.info("Batch optimization: #{optimization_result.original_count} -> #{optimization_result.optimized_count} queries (#{optimization_result.savings_percentage}% savings)")

  # Separate cached and uncached
  {cached, uncached} = Enum.split_with(optimized_texts, &EmbeddingCache.exists?(&1, @embedding_model))

  # Get cached embeddings
  cached_embeddings = Enum.map(cached, &EmbeddingCache.get(&1, @embedding_model))

  # Generate uncached embeddings (fail fast on error)
  with {:ok, uncached_embeddings} <- generate_uncached_batch(uncached) do
    # Build lookup map correctly
    optimized_to_result = Map.merge(
      Map.new(Enum.zip(cached, cached_embeddings)),
      Map.new(Enum.zip(uncached, uncached_embeddings))
    )

    # Reconstruct with O(n) lookups
    all_embeddings = reconstruct_batch_results(texts, optimized_texts, optimized_to_result)

    # Validate completeness
    if length(all_embeddings) == length(texts) and Enum.all?(all_embeddings, & &1) do
      {:ok, all_embeddings}
    else
      {:error, :batch_reconstruction_failed}
    end
  end
end

defp generate_uncached_batch([]), do: {:ok, []}
defp generate_uncached_batch(uncached) do
  start_time = System.monotonic_time(:millisecond)

  Telemetry.embedding_start(@embedding_model, length(uncached), %{batch: true})

  case generate_embeddings_batch(uncached) do
    {:ok, embeddings} ->
      duration = System.monotonic_time(:millisecond) - start_time
      total_tokens = Enum.reduce(uncached, 0, &(&2 + estimate_tokens(&1)))

      Telemetry.embedding_stop(@embedding_model, length(uncached), total_tokens, duration, %{batch: true})
      CostTracker.log_cost(:embedding, @embedding_model, total_tokens, 0, %{batch: true})

      # Cache results
      Enum.zip(uncached, embeddings)
      |> Enum.each(fn {text, embedding} ->
        EmbeddingCache.put(text, embedding, @embedding_model)
      end)

      {:ok, embeddings}

    {:error, reason} = error ->
      duration = System.monotonic_time(:millisecond) - start_time
      Telemetry.embedding_error(@embedding_model, :batch_api_error, duration, %{error: reason})
      error
  end
end

defp reconstruct_batch_results(original_texts, optimized_texts, optimized_to_result) do
  # Build reverse lookup for O(1) access
  optimized_lookup = Map.new(optimized_texts, &{String.downcase(&1), &1})

  Enum.map(original_texts, fn original_text ->
    normalized = String.downcase(original_text)
    case Map.get(optimized_lookup, normalized) do
      nil -> nil  # Should not happen with proper optimization
      optimized_key -> Map.get(optimized_to_result, optimized_key)
    end
  end)
end
```

### 5. HIGH: Caching Architecture Simplification

**Priority**: P1 (High)
**Effort**: 5 days
**Risk**: Medium - Performance impact

#### Problem Statement

Current caching uses 4 layers with unclear responsibilities:
- **Redis** (via EmbeddingCache, SearchCache)
- **Cachex** (`:ai_cache`)
- **ETS** (implicit in some caches)
- **persistent_term** (repo lookups)

This creates:
- Complexity in understanding where data is cached
- Difficult debugging (which layer has stale data?)
- Maintenance burden (multiple invalidation paths)
- Unclear performance characteristics

#### Proposed Architecture

**Keep 2 layers:**

1. **Cachex** - Application-level caching (survives process restarts via table inheritance)
   - Embedding cache (query text → vector)
   - Search result cache (thread_id + query → results)
   - Thread metadata cache (thread_id → shard_id)

2. **ETS** - Process-level caching (fast, lightweight)
   - Cost tracking (temporary operational data)
   - Participant cache (already exists)
   - JWKS cache (already exists)

**Remove:**
- Redis dependency for caching (keep for pub/sub if used)
- persistent_term for repo cache (use Cachex instead)

#### Migration Plan

```elixir
# 1. Unified cache module
defmodule GlobalbridgeBackend.AI.Cache do
  @moduledoc """
  Unified caching layer using Cachex for AI operations.
  Replaces EmbeddingCache, SearchCache, and persistent_term repo cache.
  """

  @cache_name :ai_cache

  # Embedding cache
  def get_embedding(text, model) do
    Cachex.get(@cache_name, embedding_key(text, model))
  end

  def put_embedding(text, embedding, model) do
    # 1 hour TTL for embeddings
    Cachex.put(@cache_name, embedding_key(text, model), embedding, ttl: :timer.hours(1))
  end

  def exists_embedding?(text, model) do
    case Cachex.exists?(@cache_name, embedding_key(text, model)) do
      {:ok, true} -> true
      _ -> false
    end
  end

  # Search results cache
  def get_search_results(thread_id, query, opts) do
    key = search_key(thread_id, query, opts)
    case Cachex.get(@cache_name, key) do
      {:ok, results} -> results
      _ -> nil
    end
  end

  def put_search_results(thread_id, query, results, opts) do
    # 15 minutes TTL for search results
    key = search_key(thread_id, query, opts)
    Cachex.put(@cache_name, key, results, ttl: :timer.minutes(15))
  end

  # Repo cache (replaces persistent_term)
  def get_repo(shard_id) do
    key = {:repo, shard_id}
    case Cachex.get(@cache_name, key) do
      {:ok, repo} -> repo
      _ -> nil
    end
  end

  def put_repo(shard_id, repo) do
    # Long TTL for repo references (1 day)
    Cachex.put(@cache_name, {:repo, shard_id}, repo, ttl: :timer.hours(24))
  end

  def invalidate_repo(shard_id) do
    Cachex.del(@cache_name, {:repo, shard_id})
  end

  # Cache key helpers
  defp embedding_key(text, model) do
    {:embedding, model, :crypto.hash(:sha256, text) |> Base.encode16(case: :lower)}
  end

  defp search_key(thread_id, query, opts) do
    opts_hash = :erlang.phash2(opts)
    query_hash = :crypto.hash(:sha256, query) |> Base.encode16(case: :lower) |> binary_part(0, 16)
    {:search, thread_id, query_hash, opts_hash}
  end
end
```

5. **Phase 5**: Remove Redis cache dependencies (if not used for pub/sub)
6. **Phase 6**: Update tests and documentation

      Process.delete(:thread_cache)
      conn
    end)
  end
end

# Update messages.ex
defp get_thread_with_shard(thread_id) do
  # Check process dictionary cache first
  case Process.get({:thread_cache, thread_id}) do
    nil ->
      thread = Repo.get(Thread, thread_id) || raise Ecto.NoResultsError, queryable: Thread
      Process.put({:thread_cache, thread_id}, thread)
      thread
    cached_thread ->
      cached_thread
  end
end

# 2. Fix get_message! to use get_by!
def get_message!(thread_id, message_id) do
  thread = get_thread_with_shard(thread_id)
  repo = ThreadRepo.get_repo(thread.database_shard_id)

  # Use get_by! to apply both filters correctly
  repo.get_by!(Message, id: message_id, thread_id: thread_id)
end
